=== Why a blind Hypatia pin refresh is not a fix

The caller pins standards `da2c748aad55c1a1dcba00b60fe4a35017bc6540`, but that reusable resolves moving Hypatia HEAD and builds it.
The source-keyed cache checks source identity, not successful compatibility of arbitrary scanner HEAD with the selected toolchain.
This failure also shows that the formerly last-known-good fallback mentioned in
https://github.com/hyperpolymath/standards/issues/1050[standards#1050] is not a durable workaround.
Current standards still has the same scanner build path.

A separate, executed regression exists in current standards' findings validator:

[cols="2,1,1",options="header"]
|Input |Pinned validator exit |Current validator exit
|`[]` |0 |1
|One finding with severity `warn` |0 |0
|Malformed `{` |4 |4
|Two documents: `[]` followed by an array containing a high finding |1 |0
|===

These results execute the exact jq expressions extracted from each workflow revision.
The current file-size guard still rejects zero-byte output.
The regressions are rejection of a valid clean document and loss of the exactly-one-document requirement; accepting two documents at validation does not prove the entire workflow would subsequently succeed.
The Hypatia CLI explicitly supports successful scans with zero filtered findings.
Do not confuse an empty findings array with missing output, and do not manufacture findings or suppress scanner errors to satisfy this gate.

== Foundational ownership, not another app

* *Standards*: specify scanner output/exit contracts and lifecycle acceptance. Use existing
  https://github.com/hyperpolymath/standards/issues/634[#634] and
  https://github.com/hyperpolymath/standards/issues/636[#636] for template/lifecycle coordination.
* *rsr-template-repo*: implement and test fresh-child acceptance, including branch selection, rendered identity, workflow/tool APIs and path-correct suppression configuration.
* *Scaffoldia and lifecycle orchestration*: invoke that contract; record source branch/commit/tree and intended child branch set. Do not clone its implementation into a new composer.
* *Hypatia*: distinguish source findings from build/scan/schema/upload failures, using the environmental model in
  https://github.com/hyperpolymath/hypatia/issues/448[#448] and diagnosis feedback in
  https://github.com/hyperpolymath/hypatia/issues/567[#567].
  An unexecuted scan is unavailable evidence, not zero findings.
* *Shared workflow / scanner release integration*: preserve escaped bounded primary-error annotations and diagnostic artifacts; record scanner SHA, dependency lock and toolchain; test cold/warm caches and promote tested immutable scanner revisions through a canary.
* *Fleet / branch cleanup automation*: detect and propose with provenance, deduplication and owner approval. No unattended mass edits, unrelated-history merges or age-only deletion.

Existing `.hypatia-ignore` entries were not broadened or removed.
Their prior review is not a permanent proof that future workflow changes remain safe; source-level rule precision and current fixtures are preferable to accumulating blanket exceptions.
